REQUEST PATH요청이 들어오는 길

사무실은 이중 NAT라 들어오는 포트를 열 수 없습니다. 클러스터 안의 cloudflared가 Cloudflare로 먼저 연결을 열어 두고, 요청은 그 터널을 거꾸로 타고 들어옵니다. TLS(https)는 Cloudflare에서 끝납니다.

공개 도메인 route는 X-Forwarded-Proto: https를 붙여 보냅니다. Envoy가 이 값을 http로 덮어쓰면 Keycloak과 콘솔이 주소를 http로 만들어 로그인이 깨지기 때문입니다.

TERRAFORM코드로 관리하는 스택

스택은 위에서 아래 순서로 쌓입니다. 앞 스택이 만든 것 위에서 뒤 스택이 동작하기 때문에 따로 나눴습니다. 상태 파일은 저장소 밖 ~/.claudharmony/state/에 있고, 실행은 scripts/infra.sh <스택> <plan|apply>로 합니다.

손으로 apply할 때도 배포와 같은 잠금을 잡고, 배포 기록이 원격보다 뒤처져 있으면 거부합니다. 다른 곳에서 막 배포한 이미지를 되돌리지 않기 위해서입니다.

CI/CD배포 흐름

develop push → dev
  1. 사무실 Mac 러너가 이미지 빌드
  2. DB 스키마 자동 적용 (Atlas)
  3. deploy.sh dev: kind load → apply
  4. 배포 기록을 infra에 커밋
release/YYYYMMDD → prd
  1. DB schema prd (계획·확인 문구·백업)
  2. Deploy prd (스키마 확인 후)
  3. 문제없으면 main 머지
main → console · keycloak
  1. 콘솔: deploy.sh console
  2. Keycloak 테마: deploy.sh identity keycloak
  3. Recreate 전략 · 1~2분 로그인 불가

러너는 사무실 Mac에 저장소별로 등록되어 있습니다(infra, api, web, keycloak). 레지스트리 없이 같은 Mac에서 빌드한 이미지를 클러스터 노드로 바로 넣습니다.

로그인에서 콘솔까지

  1. 홈페이지에서 로그인 → Keycloak 화면
  2. 토큰을 받은 web이 api를 호출 (aud=api)
  3. admin이면 헤더에 '관리자' 링크
  4. 콘솔은 같은 Keycloak 세션으로 바로 열림

인터넷에는 로그인 경로만 엽니다. 관리 화면과 master realm은 사무실 Mac에서만 열립니다.
